work/lifecycle-automation

Employee lifecycle automation

5 hours → 5 clicks per onboarding

Python · PowerShell · Zendesk API · Active Directory · GAM7

A joiner-mover-leaver pipeline that watches Zendesk for HR onboarding and offboarding requests, then provisions Active Directory identities, creates Google Workspace accounts, notifies the hiring manager, and opens routed child tickets for hardware and software.

It runs on an isolated host with no ingress traffic, authenticating with a group managed service account. Offboarding relocates a departing employee’s Drive data to a shared drive and grants the manager delegated access that expires automatically, so nobody keeps standing access to an account belonging to someone who has left.

work/device-data-in-ticket

Device data inside the ticket

~$9,000/year in licensing avoided

React · ZAF client · Microsoft OAuth · Graph API

Agents kept asking users questions the helpdesk should already know the answer to: what laptop is this, is it encrypted, when did it last check in. The vendor’s answer was an asset management product with a per-agent price attached.

Instead I built a sidebar app that authenticates to Microsoft and pulls the requester’s devices from Graph directly into the ticket, with a one-click write-back into an internal note so the record survives after the ticket closes.

work/tenant-consolidation

Tenant consolidation & TidyConfig

Roughly half of forms, fields, triggers, views, automations and macros retired

Python · React · Zendesk API · ZCLI

Six departments had grown a Zendesk tenant nobody could safely change: deleting a field might orphan a trigger, and nobody knew which. So the first step was mapping it, as a dependency graph of every object and every relationship between them.

The map became a tool. TidyConfig reads a tenant’s configuration, reports what is safe to remove, migrates data between fields and forms so nothing is lost on the way out, and cascades deletions to whatever would be left dangling. None of the required functionality went with it, and the forms a person actually has to choose between dropped from 22 to 7.

work/approval-repair

Purchase approval repair

Five handoffs removed · ~$50,000/year in staff hours

Python · Gmail API · ERP integration

The finance system emails purchase approvals as interactive HTML. The mail client throws that away, so approvers were opening a message with no buttons in it. The workaround had grown into a whole second system: an out-of-band document passed from approver to approver, then re-keyed by hand once it reached purchasing.

The automation detects the failure and puts the approval back where it was always meant to happen, so nobody re-keys anything and a rejection no longer restarts the whole circuit. The interesting part was that the visible problem was a rendering bug and the expensive problem was the parallel process people had built around it.
